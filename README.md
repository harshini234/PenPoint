# PenPoint

Cattle analytics and BRD decision management: a decision aid for bovine respiratory disease (BRD) in the first 45 days after feedlot arrival.
AISFS × Merck Animal Health Hackathon 2026, Problem 1.

> All demo data are **synthetic and fictional** (one invented yard). Medication-related outputs are
> decision support only and remain subject to veterinary review.

**The question it answers:** which arriving lots are high-risk for BRD, why, and is metaphylaxis worth its cost for each
one at 2026 prices? Risk comes from a decision tree built the way Rojas et al. (2022) built theirs, and the costs use their
net health cost benefit equations (Eqs 1-5). Every calculation in the app has a "Show the work" note with the numbered
equation, the variables and today's numbers plugged in.

**One rule it never breaks:** no plan may have more expected BRD deaths than current practice (with a 5% safety
margin). The tool saves money and antimicrobial doses only where that doesn't cost cattle; the stress tests in
`docs/evaluation.md` check that this holds even when our assumptions are wrong.

## Run it

```bash
python -m pip install -r requirements.txt
python -m streamlit run app/streamlit_app.py
```

PenPoint starts **empty**: there is no preloaded yard. Load data one of two ways:

- **In the app:** Lot management → Add or import data → upload the files in `demo_data/` (or your own) → Import.
- **From the command line:** `python scripts/import_demo.py` (demo files) or `python scripts/import_demo.py my_cattle.csv my_health.csv`.

### Demo data (`demo_data/`)
| File | What's in it |
|---|---|
| `cattle.csv` | 1,972 cattle in 18 lots, one row per animal with its lot's details (weight, haul time, preconditioning, vaccination, buyer's call, channel, pen size) |
| `health_records.csv` | 132 records: first BRD treatments (florfenicol), retreatments (enrofloxacin), deaths, with temperatures, withdrawal days and who treated |
| `sensehub_alerts.csv` | One day's SenseHub alert report (16 alerts) |

All fictional, generated by `scripts/make_demo_data.py` from the calibrated simulation. Records run to Nov 14, 2026, so importing sets PenPoint's date to that day (change it under Constraints and assumptions).

### Database: PostgreSQL
PenPoint stores everything (lots, cattle, health records, uploads, settings, protocol) in a database, not the browser.

- **PostgreSQL (recommended, and required for a shared deployment):** set `DATABASE_URL`, either as an environment variable or in `.streamlit/secrets.toml` (see `.streamlit/secrets.toml.example`). Free hosted options: Neon or Supabase; paste their connection string. For a local server: `docker compose up -d`, then `export DATABASE_URL=postgresql://penpoint:penpoint@localhost:5432/penpoint`.
- **Without `DATABASE_URL`** PenPoint falls back to a local SQLite file, `data/penpoint.db`, and says so in the sidebar.

Tables are created on first run. On Streamlit Community Cloud, add `DATABASE_URL` under the app's Secrets; local files there are wiped on restart, so use PostgreSQL.

### Deploy (free, no paid access)
1. Push this folder to a public GitHub repo.
2. share.streamlit.io → **Create app** → repo, branch `main`, main file `app/streamlit_app.py`.
3. Advanced settings → Secrets: `DATABASE_URL = "postgresql://..."` (from Neon or Supabase) → Deploy. Then import the data in the app.

### Rebuild everything from scratch (about 1 minute)

```bash
python scripts/calibrate.py            # fit 5 generator values to Rojas 2022 + Cernicchiaro 2011 -> params/calibrated.yaml
python scripts/generate_data.py        # data/demo/*.csv (seeded)
python scripts/validate_generator.py   # docs/generator_validation.md
python scripts/evaluate_policies.py    # data/eval/results.csv + docs/evaluation.md
python scripts/demo_case.py            # docs/demo_case.md
python scripts/make_data_dictionary.py # docs/data_dictionary.md
python scripts/export_ledger.py        # params/parameter_ledger.csv
```

## What's in the app

| Section | Pages |
|---|---|
| **Lot management** | **Lots and cattle**: lots ranked by risk; herd values with the work shown (weight, haul time and pay weight are averaged over the animals; sex, preconditioning and vaccination are lot categories, and an animal that differs is flagged as a conflict). Open a lot for every animal: status (in treatment, retreated, recovered, died…), slaughter-withdrawal date, and a health history where each treatment shows its number, drug, product, class and route, editable. **Add or import data**: bulk import, a lot by hand (or from a health certificate), cattle one at a time, as a group or from a file, and the daily SenseHub report. **Constraints and assumptions**: costs (2026 defaults), risk-factor odds ratios, the vet's treatment protocol, current practice, no-more-deaths margin, hospital spaces, date. |
| **Herd status** | **Risk overview**: counts of high-risk, not-sure and low-risk lots; a table of lots ranked by risk score (select one for the reasons behind its rating); and the cattle that need attention today (in treatment or flagged by SenseHub). Risk only, no instructions. |
| **Management options** | **Treatment options** (opens here): the recommended plan in plain words with its cost, deaths and antibiotic doses against the current approach; the four options side by side; each arriving lot's two costs, with close calls flagged for the vet · **Lot-level cost analysis** (TP / FP / FN / TN, Rojas Eqs 1-5) · **Scenario analysis** (what-if sliders, unsaved) · **Decision summary** (download for vet review and signature) · **Daily action list** · **Treatment response** |
| **About the model** | **Methods and equations** · **Model validation** · **Parameter sources** · **Brief requirements** (each dashboard requirement in the brief, with a button to where it's met) |

## Verifying the parameter ledger
For each entry in `params/parameters.yaml` (or `params/parameter_ledger.csv`):
1. Open `link` and go to `location`. Entries marked `abstract` or `secondary` need the full text or the primary source.
2. Confirm the value; fix it if wrong.
3. Set `verified: true` and add `verified_by: <initials>`.
4. If a generator value changed, rerun the rebuild sequence above.

## Honest limits
- Synthetic data. The tree learns from simulated yard history calibrated to the paper's published figures; a yard's own
  records would replace it. Its accuracy numbers describe the simulation, not real cattle.
- Rojas Eq 3 as printed multiplies by TC and uses BRD45; PenPoint uses CS and the BRD rate of a high-risk lot so the units work
  (explained on the equations page).
- With few high-risk lots in history, the Youden cutoff is low (about 8.5%), so many lots are called high risk; the risk score
  and the costs show how strong each call is.
- The risk-factor adjustment uses one observed odds ratio (preconditioning 0.54, Mijar 2023) and four labelled assumptions
  (vaccination, haul ≥ 6 h, sale barn, weight); all are editable.
- The drug protocol is an example for the demo; the veterinarian sets the real one and the product labels govern doses and withdrawal.
- 43 of 90 parameters are labelled assumptions, mainly effect magnitudes where sources give only direction.
- 2026 metaphylaxis cost is a placeholder (get a quote). The Mexico-origin effect is an unsourced hypothesis.
- Weather is a synthetic climatology; swap in Mesonet station data (manual download).
